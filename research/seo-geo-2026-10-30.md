# SEO, GEO и доступность DESTINY для LLM

Дата проверки источников: 30 октября 2026 года. Документ описывает решения для статического сайта <https://destiny.by/>; он не включается в опубликованный артефакт GitHub Pages.

## Приоритеты

Основой служат содержательный HTML, доступные ссылки, корректная индексация и согласованные сведения об услугах. Google применяет обычные SEO-требования к AI Overviews и AI Mode: для участия страница должна быть индексируемой и допускать показ фрагмента. Отдельный AI-файл или особая Schema.org-разметка не требуются. Это не означает, что участие или цитирование гарантированы. [Источник: Google, AI features and your website](https://developers.google.com/search/docs/appearance/ai-features).

После обратной связи владельца сайт разделён по задачам посетителя: краткая главная, четыре самостоятельные страницы услуг, подход и FAQ, пример отчёта и контакты. Страницы услуг имеют собственные канонические адреса и содержание. Вспомогательные страницы конфиденциальности и ошибки не индексируются. Географические и поисковые дубли не создаются.

## Карта решений

| Область | Решение |
| --- | --- |
| Главная | Краткое предложение, каталог услуг и ссылки на их самостоятельные страницы |
| Услуги | Собственные canonical и Service-сущности, конкретный предмет проверки и результат |
| Подход | Этапы работы и FAQ, извлечённый в разметку из видимых ответов |
| Контакты | ContactPage, опубликованные email и ссылка на LinkedIn |
| Пример отчёта | Открыт для индексации как самостоятельный полезный материал; демонстрационные сценарии явно обозначены |
| Конфиденциальность | `noindex, follow`, собственный canonical, исключение из sitemap |
| Отсутствующие страницы | `noindex` и штатная страница ошибки GitHub Pages; неизвестный адрес должен возвращать HTTP 404 |
| Sitemap | Только канонические индексируемые HTML-страницы, без фрагментов, ошибок и вспомогательных файлов |
| Разметка | Связанные Schema.org-сущности компании, сайта, страниц и услуг, вопросы/ответы, демонстрационный отчёт и навигационные цепочки |
| Машиночитаемый экспорт | `ai.json` содержит тот же граф JSON-LD и устойчивые `@id`, что HTML |
| Текстовые представления | `llms.txt`, `llms-full.txt` и Markdown-копии восьми индексируемых страниц |
| Производительность | Локальные шрифты, WOFF2, сохранённые размеры изображений и приоритет главного изображения |
| Поддержка | Один генератор из исходного HTML и `seo/site.json`; проверка согласованности перед публикацией |
| Уведомление об обновлении | Один IndexNow POST после успешного deploy, только для индексируемых HTML-страниц |

Sitemap помогает обнаружить выбранные адреса, но является подсказкой, а не гарантией обхода или индексации. `lastmod` должен обозначать содержательное изменение страницы. [Источник: Google, Build and submit a sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

`noindex` размещается в метатеге страницы. Обход такой страницы не блокируется в robots.txt: поисковику необходимо прочитать директиву. Для неизвестных адресов сохраняется настоящий HTTP 404, а не страница с кодом 200, маскирующая ошибку. [Источники: Google, robots meta tag](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag); [GitHub, custom 404 page](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-custom-404-page-for-your-github-pages-site).

## Что означает ai.json

`/ai.json` — выбранный для этого сайта адрес публикации стандартного Schema.org JSON-LD. Это не отдельный общепринятый AI-стандарт, не API для запуска пентеста, не OpenAI plugin manifest и не регистрация сайта у провайдера моделей. Он позволяет получить согласованные сущности и ссылки одним запросом.

Описания и результаты услуг берутся из соответствующих страниц услуг; ответы — из `approach.html`. Эти сведения совпадают с HTML, который читает посетитель. В разметку не добавляются рейтинги, цены, сертификаты, физический адрес, юридическое название или контактные каналы, если они не подтверждены. Партнёры из блока доверия не записываются в `sameAs`: это другие организации. Пример отчёта остаётся демонстрацией, а не доказательством выполненного клиентского проекта. [Источник: Google, Structured data general guidelines](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).

Разметка FAQ описывает уже опубликованные вопросы и ответы. Она не обещает расширенный FAQ-сниппет: Google прекратил показ этого формата в мае 2026 года и удалил соответствующую документацию в июне. [Источник: Google Search documentation updates](https://developers.google.com/search/updates#removing-faq-rich-result).

## llms.txt и Markdown

`llms.txt` реализован как указатель на основные материалы; `llms-full.txt` объединяет их текстовые представления. Markdown-копии связаны с HTML через `rel="alternate" type="text/markdown"`; `rel="describedby"` указывает на `llms.txt`. Это соответствует опубликованному предложению llms.txt, но не заменяет robots.txt, sitemap или HTML. [Источник: llms.txt proposal](https://llmstxt.org/).

Формат полезен потребителям, которые его поддерживают. Наличие файла само по себе не доказывает, что Google, ChatGPT, Claude или Perplexity его прочитали либо будут цитировать сайт. Google отдельно разъяснил, что llms.txt не требуется Google Search и не влияет положительно или отрицательно на видимость и ранжирование. [Источник: Google Search documentation updates, 15 June 2026](https://developers.google.com/search/updates).

## Поисковые боты и обучение

Сохранён существующий общий `Allow: /`; поисковым AI-ботам доступ указан явно. Это не меняет прежнюю политику для ботов обучения.

| Провайдер | Поисковый агент | Отдельное назначение |
| --- | --- | --- |
| OpenAI | `OAI-SearchBot` | `GPTBot` связан с обучением; `ChatGPT-User` выполняет запросы по инициативе пользователя |
| Anthropic | `Claude-SearchBot` | `ClaudeBot` связан с обучением; `Claude-User` обращается к страницам по запросам пользователей |
| Perplexity | `PerplexityBot` | `Perplexity-User` обслуживает запросы пользователей; поисковый бот не предназначен для обучения фундаментальных моделей |

Официальные источники: [OpenAI Crawlers](https://developers.openai.com/api/docs/bots), [Anthropic web crawlers](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler), [Perplexity Crawlers](https://docs.perplexity.ai/docs/resources/perplexity-crawlers). Robots.txt выражает правила для соблюдающих их роботов и не является контролем доступа.

## Публикация и сопровождение

Контент редактируется в HTML, метаданные — в `seo/site.json`. Команда `python3 scripts/build_discovery.py` обновляет встроенную разметку и файлы обнаружения. Команда с `--check` проверяет согласованность сохранённых представлений; она выполняется в GitHub Actions до упаковки.

Публикуются только HTML и Markdown из явного списка `seo/site.json`, ресурсы, robots, sitemap и общие машиночитаемые файлы. `README.md`, `research/`, `seo/` и `scripts/` остаются в репозитории. Виртуальный сервер, платный сервис SEO и внешние пакеты Python не нужны.

### IndexNow

После успешного deploy Actions запускает `scripts/notify_indexnow.py`. Он отправляет текущие индексируемые адреса из `seo/site.json` на общий официальный endpoint `https://api.indexnow.org/indexnow`. Адрес POST опубликован в [официальном FAQ IndexNow](https://www.indexnow.org/faq) и подтверждён [инструкцией Bing](https://www.bing.com/indexnow/getstarted). Протокол предусматривает передачу уведомлений между участвующими поисковиками; участие Google не заявляется.

Вместе с сайтом публикуется постоянный `indexnow-key.txt`. Это публичный файл подтверждения контроля домена; он создан один раз, не ротируется при публикации и не содержит учётных данных. Поле `keyLocation` явно указывает его адрес в корне сайта. Перед отправкой скрипт проверяет, что опубликованный файл совпадает с локальным значением. При недоступности или задержке CDN он выдаёт предупреждение и не отправляет URL.

Каждое сетевое обращение ограничено десятью секундами, перенаправления не принимаются, циклов повторной отправки и задержек нет. Шаг CI использует `continue-on-error: true`: сбой поискового сервиса не делает недоступным уже опубликованный сайт. HTTP 200 подтверждает получение; 202 означает, что проверка ключа ещё ожидается. Ни один из статусов не подтверждает индексирование. [Источник: IndexNow documentation](https://www.indexnow.org/documentation).

Локальная команда `python3 scripts/notify_indexnow.py --dry-run` показывает endpoint и адреса без обращения к сети. Реальное уведомление выполняет только шаг после успешной публикации; оно не подключает поисковый аккаунт и не заменяет подтверждение сайта в кабинетах владельца.

Возможности GitHub Pages ограничены статической публикацией. Серверные обработчики форм, произвольные правила HTTP-заголовков и перенаправления не имитируются неработающими конфигурационными файлами. Основной домен и HTTPS задаются через Pages/DNS. [Источник: GitHub Pages custom domain](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site).

## Что требует аккаунта владельца

Google Search Console и Bing Webmaster Tools подключаются после подтверждения владения доменом. Владелец подаёт `https://destiny.by/sitemap.xml`, наблюдает индексирование и поисковый трафик, при необходимости запрашивает повторный обход. Проверочные токены и записи DNS нельзя получить из содержимого лендинга; фиктивные значения в сайт не добавлены. [Источники: Google, AI features and your website](https://developers.google.com/search/docs/appearance/ai-features); [Bing Webmaster Guidelines](https://www.bing.com/webmasters/help/webmaster-guidelines-30fba23a).

Обновление контактов от 31 октября 2026 года: по просьбе владельца сайт использует прямые ссылки на `https://www.linkedin.com/in/vadimohka/` и `mailto:security@destiny.by`. Формы и внешний почтовый обработчик удалены. Email опубликован на странице контактов и в Organization. Личный профиль LinkedIn указан как `relatedLink` страницы ContactPage; он не записывается в `sameAs` организации. Обе ссылки доступны в текстовом представлении контактов. Нажатие на ссылку само по себе не означает отправку сообщения. Свойство `relatedLink` связывает WebPage с относящимся к ней URL. [Источник: Schema.org, relatedLink](https://schema.org/relatedLink).
